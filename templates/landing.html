{# ── How it works (3 steps) ───────────────────────────────────── #}

Three steps, fully automatic

From a public GitHub URL to a documented, drift-monitored codebase.

Connect a repository

Paste a public GitHub URL. DocDrift shallow-clones it and maps every module, class, and public function with Python's ast.

Generate documentation

An LLM writes a Google-style docstring for each entity. Unchanged code keeps its docs on re-runs — you only pay for what changed.

Detect drift

Re-analyze anytime. DocDrift compares snapshots and flags stale docs, signature changes, new undocumented code, and orphaned docs.

{# ── Drift types (the unique selling point) ───────────────────── #}

Four kinds of drift, caught automatically

Every snapshot comparison produces one or more of these flags, each with a real unified diff attached.

stale_doc

Code body changed, prior doc preserved. Review the diff and regenerate just this one when you're ready.

signature_changed

A parameter was added, removed, or renamed. The old and new signatures are stored side-by-side.

new_undocumented

Code that exists in the current snapshot but has no docstring and was never seen before.

orphaned_doc

A function or class that was documented in the previous snapshot but no longer exists.
