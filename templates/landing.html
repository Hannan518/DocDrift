{# ── 2 · How it works: horizontal timeline ────────────────────── #}
Pipeline

Three steps, fully automatic

From a public GitHub URL to a documented, drift-monitored codebase.

01

Connect a repository

Paste a public GitHub URL. DocDrift shallow-clones it and maps every module, class, and public function with Python's ast module — signatures, source hashes, and class-method links included.

02

Generate documentation

An LLM writes a Google-style docstring for every undocumented entity. Unchanged code keeps its docs on re-runs — hash-based change detection means you only pay tokens for what changed.

03

Detect drift

Re-analyze anytime. DocDrift compares snapshots and flags stale docs, signature changes, new undocumented code, and orphaned docs — each with a real unified diff attached.

{# ── 3 · Drift types with real diff snippets ───────────────────── #}
Drift detection

Four kinds of drift, caught automatically

Every snapshot comparison produces flags with the actual diff attached — not just a warning.

stale_doc

Code body changed, prior doc preserved for review.

- return sum(items)- + return sum(items) * (1 + tax)

signature_changed

A parameter was added, removed, or renamed.

- def total(items: list)+ def total(items, tax: float = 0.0)

new_undocumented

New code that exists without any documentation.

+ def validate_email(addr: str) -> bool  no docstring found

orphaned_doc

Documented code that no longer exists.

- def legacy_import(rows):  removed, doc still on file
